## Decisions

- Validation lives in `packages/domain/src/notes.ts`: Note trimmed, at most 500 (UTF-16 length, never below `char_length`), and an empty Note clears to `null`. A Tag is trimmed, 1–24 characters, and unique per Photo by `toLowerCase()`. The same file holds `historyTags` (filter chips: each Tag once, case-insensitively, first spelling kept, in order of first appearance) and `filterHistory` (`"all" | "note" | { tag }`), shared by both apps.
- DB backstops mirror the domain: `photos_note_length` check (`char_length(note) <= 500`), `photo_tags_label_length` check (1–24), and a unique index on `(photo_id, lower(label))`, so case-insensitive uniqueness holds in Postgres too. `lower()` folds non-ASCII only under a Unicode-aware ctype: unverified on production, check SQL in Next step 1.
- `photo_tags` has no `created_at` (the spec lists none), so the DB returns Tags in no guaranteed order (insertion order in practice); the screen appends new ones at the end.
- RLS is `ownerOnly` like `spots`/`zone_readings`: it checks `user_id`, not that `photo_id` belongs to the same user. A user who knew another user's photo uuid could attach a Tag row to it that only they can see; this matches the existing child tables, so it was left alone.
- Migration generated as `0004_notes_and_tags.sql` (`--name notes_and_tags`), NOT applied.
- The Note saves on blur, only when valid and changed, and a quiet "Đã lưu" / "Saved" status confirms it. There is no save button: the canvas draws none, and the one filled button per screen is not needed here. The Textarea is borderless inside the canvas card; focus shows as a stronger card border (web).
- "Thêm tag" turns into an input: Enter (web) or the keyboard submit (Android) adds; Escape (web) or leaving it empty and blurring cancels. Errors show inline under the Tags, one line at a time. The input has no `maxLength`, so the too-long message can show.
- New strings (vi / en): Ghi chú / Note, "Đêm nay có gì khác?" / "What was different tonight?", "Ghi chú tối đa 500 ký tự." / "Keep the note to 500 characters.", Đã lưu / Saved, "Không lưu được ghi chú. Thử lại sau." / "Couldn't save the note. Try again later.", Tag / Tags, Thêm tag / Add tag, Tag mới / New tag, "Xóa tag {label}" / "Remove tag {label}" (remove button name), "Nhập tên tag." / "Type a tag name.", "Tag tối đa 24 ký tự." / "Keep tags to 24 characters.", "Ảnh đã có tag này." / "This photo already has that tag.", "Không lưu được tag. Thử lại sau." / "Couldn't save the tags. Try again later.", Lọc ảnh / Filter photos (web chip group name), Tất cả / All, Có ghi chú / Has a note, "Không có ảnh nào khớp bộ lọc." / "No photos match this filter."
- Delete dialog body lists the kinds, not the Tag names: "Xóa ảnh, nốt mụn, chỉ số, ghi chú và tag của đêm {date}. Không thể khôi phục." (canvas wording plus "và tag").
- Filter chips are single-select (`aria-pressed` on web, `aria-selected` on Android). They appear only when there are Photos, "Có ghi chú" is always shown (canvas), and a tagged tile carries the canvas tag icon at top right.
- Android Tags are a `View` chip plus a 44px `Pressable`, not RNR Badge: Badge is not installed, and a restyled Badge would be the same View. Same reasoning as ticket 20's checkbox, so the RNR CLI was not run and nothing in `components/ui` changed. Android uses the RNR `Textarea` and `Input` already installed.
- Xem thử supports Notes/Tags cheaply: `lib/demo.ts` keeps `notes` and `tags` in the demo store (this browser only, cleared by Đặt lại). The generated persona has no Notes or Tags.
