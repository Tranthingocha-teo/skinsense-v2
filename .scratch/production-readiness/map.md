## Decisions so far

- [Domain package input boundary](issues/03-domain-input-boundary.md): `packages/domain` accepts `{ landmarks, mask }` from each platform and computes zone polygons + redness/unevenness itself, once — not pre-built polygons per app. Recorded as [ADR 0001](../../docs/adr/0001-domain-package-receives-landmarks-and-mask.md). Note: the ticket's original framing assumed a 468-vs-478-point platform split that turned out to be wrong — both are 468-point in the final wire *contract* (web's raw `FaceLandmarker` output is still 478 at runtime; the contract drops its 10 iris points, native's raw tensor is natively 468); see ticket [05](issues/05-landmark-mask-wire-format.md) for the final correction.
- [Domain package schema ownership](issues/04-domain-schema-ownership.md): `packages/domain` owns the DB schema; Supabase migrations generate from it (inverts Supabase's usual DB-first workflow). Recorded as [ADR 0002](../../docs/adr/0002-domain-owns-db-schema.md). Entities `Photo`, `Spot`, `ZoneReading`, `RoutineEntry` added to `CONTEXT.md` while resolving this ticket.
- [Landmark + mask wire format](issues/05-landmark-mask-wire-format.md): 468 points on both platforms (not 478 — corrects ADR 0001's original claim), `[0,1]`-normalized x/y with z kept, mask = pre-reduced binary `Uint8Array` (amended after finding the internal `mediapipe-tflite` skill already specified this `FaceCapture` shape). Recorded as an update to [ADR 0001](../../docs/adr/0001-domain-package-receives-landmarks-and-mask.md). Spun out: [Zone-to-landmark index map](issues/06-zone-landmark-index-map-research.md) (research), [Mask resolution and alignment spike](issues/07-mask-resolution-alignment-spike.md) (task).
- [Mask resolution and alignment spike](issues/07-mask-resolution-alignment-spike.md): verified empirically (not from docs) on web only — mask resolution tracks the input canvas exactly (640×480, not a fixed 256×256), and landmark-normalized `[0,1]` coordinates index the mask's pixel grid directly (centroid→face-skin, corners→background). Native is unverified — no capture code exists yet to test against; left as implementation-time risk.
- [Redness-index validation bar](issues/01-redness-validation-bar-research.md): no consumer app found publishing a validation methodology (Trace, SelfieLog both disclaim clinical grading, trend-only). Literature gives partial analogs, no single off-the-shelf method: monotonicity has a controlled-stimulus precedent (Frew et al. Q-score, PMC8049083), small-N rank agreement exists but against clinician grading not lay raters (same paper + Logger et al., PMC7754330), test–retest repeatability and reference-patch checks are largely unconfirmed in the sources reached. Full findings in the ticket's Answer; feeds ticket 02.
- [Redness-index acceptance bar](issues/02-redness-acceptance-bar-decision.md): automated Vitest fixture test in `packages/domain` — monotonicity across a few of Dinh's own test photos with deliberately increasing visible redness, plus small-N rank agreement against a human ranking of the same photos. Fixtures are pre-extracted `{ landmarks, mask }` + `a*` data from Dinh's own photos via the web pipeline (not raw images — `packages/domain` has no I/O), acceptable given the repo is private. Recorded as [ADR 0003](../../docs/adr/0003-redness-index-acceptance-bar.md). Follow-up grilling pass 2026-09-11 (triggered by a `/code-review` pass on the ADR) locked solo rater + a Stop-hook test gate (not CI — this repo has none) and widened the separate synthetic test to full-pipeline; surfaced a fixture-generation tooling gap, spun out as ticket 08. A second `/code-review` pass then caught the ADR's first draft of this wrongly calling the Stop-hook gate "CI" — corrected same day.
- [mpbench fixture-generation harness](issues/08-mpbench-fixture-harness.md): built as a new workspace `mpbench/` (Playwright + the real web pipeline in `bench.html`, zone classification in `run.ts` via `@skinsense/domain`'s real `assignSpotToZone` — no duplicate zone logic). Surfaced that ADR 0003's original fixture-shape wording (`landmarks+mask+precomputed a*`) didn't match `computeZoneReading`'s actual signature (raw RGB per zone); corrected in ADR 0003's Addendum 3. Fixture JSON lands in `packages/domain/src/__fixtures__/redness/`; source photos gitignored. Not yet run against a real photo — no fixtures exist yet. Out of scope: the fixture-consuming test itself (separate follow-up).
- [Native capture adapter verification](issues/09-native-adapter-verification.md): **resolved 2026-09-12**, folded into `skin-diary-v1` [issue 08](../skin-diary-v1/issues/08-mobile-capture.md) as a real acceptance criterion (issue 08 now also blocked by issue 07, since the comparison needs both platforms' capture to exist).
- [ADR 0003 acceptance-bar test: consume mpbench's fixtures](issues/11-fixture-consuming-test.md): **resolved 2026-09-12**, folded into `skin-diary-v1` [issue 15](../skin-diary-v1/issues/15-fixture-acceptance-test.md) — new ticket, no blockers, scheduled early per the same `/grill-me` pass rather than deferred to the end.
- [Zone-to-landmark index map](issues/06-zone-landmark-index-map-research.md): no official MediaPipe region exists for the four skin-zone groupings (forehead/cheeks/nose/chin) — community-sourced index lists, cross-checked against ≥2 independent repos plus py-feat's anatomical muscle-seed maps and the canonical mesh diagram. Eye/eyebrow/lips exclusions confirmed official (`face_mesh_connections.py`); nostrils and chin have thin, seed-point-only evidence. Full index lists and confidence levels in the ticket's Answer; landed directly in `packages/domain/src/zones.ts`.
- [Routine checklist contents](issues/10-routine-checklist-decision.md): user-customizable, itemized. New entity `RoutineItem` (user-owned, ordered, reorderable); new users get a seeded default set. `RoutineEntry` snapshots completed items' labels at tick time, not `RoutineItem` id references, so later renames/deletes never change past nights or the completion-% trend. Ticking is independent of `Photo`. Recorded as [ADR 0004](../../docs/adr/0004-routine-checklist-user-customizable.md); `CONTEXT.md`'s `RoutineEntry` gap resolved, `RoutineItem` added.
- [Native adapter verification](issues/09-native-adapter-verification.md): resolved 2026-09-13 by skin-diary-v1 ticket 18 — same JPEG through both adapters: landmarks 1.8 px mean from web, masks agree to 0.2 % once native uses web's `selfie_multiclass_256x256.tflite` (`selfie_segmentation.tflite` needs a MediaPipe custom op plain TFLite lacks), zone redness rank-equal with a 0.2–0.9 a* offset; readings are comparable per platform, not calibrated across.
