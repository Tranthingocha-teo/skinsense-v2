# Redness index ships with a monotonicity + small-N rank-agreement self-check, not clinical validation

Before shipping, `packages/domain`'s redness index gets an automated Vitest fixture test: it must (1) increase across a small set of Dinh's own test photos with deliberately increasing visible redness, and (2) match a small human rank-ordering of those same photos by visible redness. This replaces clinical-grade validation, which research (wayfinder ticket [01](../../.scratch/production-readiness/issues/01-redness-validation-bar-research.md)) found no comparable consumer app (Trace, SelfieLog) publishes either, and which the only quantitative precedents in the literature (Frew et al., Logger et al.) achieved only with dermatologist involvement — not a few-hours solo-dev task. The fixtures are pre-extracted `{ landmarks, skinMask }` plus per-pixel `a*` data, derived once from real photos of Dinh's own face via the web capture pipeline (per ticket [07](../../.scratch/production-readiness/issues/07-mask-resolution-alignment-spike.md), the only verified path — native has no capture code yet) and committed to `packages/domain`'s test fixtures. Not raw photo files: `packages/domain` stays pure TypeScript with no I/O, per [ADR 0001](./0001-domain-package-receives-landmarks-and-mask.md). Committing the derived data is acceptable because the GitHub repo is private.

**Addendum (2026-09-11, follow-up grilling pass on this ADR):** two previously-open points locked. Rank-agreement rater: Dinh only, no additional raters — simpler, and fits the few-hours solo-dev framing this ADR already assumes elsewhere. Test-failure handling: a failing fixture test blocks the agent from ending its session — not a CI gate (this repo has none, no `.github/workflows`), but the same local Stop-hook mechanism `.claude/hooks/typecheck-on-stop.sh` already uses for `tsc`, extended to also run `packages/domain`'s Vitest suite; when a redness-formula change is intentional and legitimately shifts monotonicity or rank order, the fixture data and expected order must be updated in the same PR with an explanation of why the shift is expected, not silently adjusted. Fixture count ("2-3"/"a handful") and exact assertion strictness (strict order vs. tolerance) stay deliberately unlocked, as originally decided — re-examined in the same pass and reaffirmed, not settled further.

**Addendum 2 (2026-09-11, same day, after a code-review pass on this ADR):** the fixture test alone never exercises the sRGB→CIELAB conversion inside `packages/domain` — fixtures store pre-computed `a*`, so a conversion bug (wrong gamma, wrong matrix, swapped channel) wouldn't be caught. Closed by widening the separate synthetic-data test (see [ticket 02](../../.scratch/production-readiness/issues/02-redness-acceptance-bar-decision.md)'s Answer) from aggregation-math-only to a full-pipeline synthetic check (flat-colour and red-patch synthetic images), matching the `mediapipe-tflite` skill's own test plan — no fixture-design change needed. Separately: the `mpbench`-based pipeline this ADR relies on for producing fixtures does not exist in this repo yet (see [ticket 08](../../.scratch/production-readiness/issues/08-mpbench-fixture-harness.md)) — the Stop-hook-gate regeneration requirement above has no tooling behind it until that ticket resolves.

**Addendum 3 (2026-09-12, resolving ticket 08):** the fixture shape above (`{ landmarks, skinMask }` + precomputed `a*`) doesn't match what `packages/domain` actually implements — `computeZoneReading` (in `redness.ts`) takes raw RGB pixel arrays per zone and converts to `a*` internally, not precomputed `a*` values. Fixtures are instead raw RGB pixel arrays, partitioned per zone plus one `allSkinPixels` array, generated by `mpbench` (see ticket 08's Answer) reusing `packages/domain`'s own `assignSpotToZone` to do the pixel→zone classification — so the fixture-generation step exercises the same zone logic the app ships, not a second copy of it. This still keeps `packages/domain` free of I/O: it receives arrays, never reads landmarks/mask/images itself. Source photos are gitignored, not committed — more sensitive than derived pixel data even in a private repo; only the derived fixture JSON is committed, matching this ADR's existing "committing derived data is acceptable" reasoning.

**Addendum 4 (2026-09-12, `/grill-me` pass after two research passes):** the acceptance bar above measured the wrong thing, and the rank-agreement half of it could not have proved anything. Both are corrected here.

*What must increase.* `redness(zone) = median(a*_zone) − median(a*_allSkin)` is self-referenced **within one photo**, so a whole-face flush raises both terms and the index does not move. "Photos with deliberately increasing visible redness" is therefore unachievable as written: what has to increase is **one zone's redness relative to the rest of the same face**. Fixtures are now produced by a designed local stimulus — a comfortably warm (~40 °C) compress applied to the **left cheek only**, in cumulative doses of 0/2/4/6/8 minutes, one photo after each dose (dried and settled ~30 s first, so specular sheen doesn't confound `a*`). This also replaces the earlier attempt to substitute other people's photos, which failed for the same self-referencing reason (see ticket 15's `## Now`).

*Rank agreement is dropped.* With the dose order known by construction, a rating by the same person who applied the doses is not independent evidence — it is the design re-stated (criterion contamination; Guilford, and the general criterion problem in validity theory). Blinding would restore independence, but at these sizes it buys almost nothing: with n=5 only a **perfect** blinded ranking reaches conventional significance (exact two-sided p ≈ 0.017 — a single adjacent swap gives ≈ 0.083), and n=4 cannot reach it even when perfect. Colorimetry studies using a graded stimulus report the instrument's dose-response, not rater agreement (e.g. Dornelles 2004, a* rising 0.99 → 2.7 across UV-B doses). The clause is removed rather than blinded.

*The bar, restated.* The committed fixture test asserts (1) the **left cheek's** `redness` increases monotonically across the five doses, and (2) the **right cheek's** `redness` stays within a measured noise floor — three consecutive photos taken at dose 0 with nothing changed, their largest spread taken as that camera's and that room's repeat-photo noise. The control half is what catches a whole-image drift that monotonicity alone would pass. The noise floor is measured **before** the dosed series, not chosen after seeing the results.

*What may be claimed.* "On one subject, the treated cheek's index increased monotonically with cumulative warm-compress dose (0–8 min, n=5) while the contralateral cheek stayed within repeat-photo noise." Not "the index tracks visible redness", not "validated", not "correlates with clinical erythema" — those need multiple subjects, blinded raters, and a quantified noise floor this bar does not establish. Fixture count is now fixed at 7 photos (3 at dose 0, the first of which is the series' own dose-0 point, plus 4 dosed at 2/4/6/8 min), superseding the deliberately-unlocked "2-3"/"a handful" from Addendum 1. The test also asserts the left cheek's swing from dose 0 to dose 8 **exceeds** the noise floor: without that clause, five readings all sitting inside the noise would satisfy "monotonic" by chance and the gate would be vacuous.

*Camera conditions* (the one primary source found, arXiv 2411.13832, reports ITA° SD 0.34°–1.04° under these): auto white balance off, flash off, manual exposure fixed, fixed distance and angle, unchanged room lighting for the whole session. No source was found giving an `a*` effect size for a warm compress, so whether the stimulus clears this noise floor is unverified until the photos are measured — which is why `mpbench generate` now prints each zone's `computeZoneReading` output, so the series can be checked on the spot rather than after the session.

**Addendum 5 (2026-09-14, Dinh's decision in session):** the real-skin fixture test is **dropped, not deferred**. The test was written on 2026-09-14 (`redness.fixture.test.ts`, the three Addendum 4 clauses, proven on synthetic fixtures) and deleted the same day, before any photo session: Dinh chose not to run the warm-compress protocol. What ships is only the synthetic full-pipeline check from Addendum 2 (`redness.test.ts`: flat-colour vs red-patch, sRGB→CIELAB end to end). The claim that may be made shrinks accordingly: "the index is a within-photo relative measure of CIELAB a*; it has not been checked against real skin". The Stop hook keeps running `packages/domain`'s Vitest suite — it gates the 55 remaining domain tests, not this one. `mpbench generate` still writes fixture JSON, unused; left in place because `rate` and `live` share the harness. Reversible: [ticket 15](../../.scratch/skin-diary-v1/issues/15-fixture-acceptance-test.md) keeps the protocol and the test's design, so the session can be run and the test restored from commit `e28da31` if a future reviewer asks for real-skin evidence.

**Addendum 6 (2026-09-14, `/grill-me` risk re-check):** web and native readings of the same face differ by 0.2–0.9 `a*` per zone (rank-equal, [ticket 18](../../.scratch/skin-diary-v1/issues/18-native-capture-spike.md)), and `photos` records no platform, so a user who captures on both sees the two mixed in one trend line. Accepted as a known limitation, no schema change before submission: readings are comparable within one platform, not across.

## Considered Options

- No check at all: rejected — research found no evidence either way that this is acceptable practice, and an automated regression test costs little more than a manual one-off once fixtures need capturing anyway.
- Test–retest repeatability or a known-reference-patch check: rejected — weakest, largely unverified literature precedent reached (one paywalled colorimeter paper, snippet-only), and a reference-patch check is misaligned with the index's self-referenced design, which `redness-index.md` already notes doesn't need absolute calibration.
- Manual one-time check, not committed to the repo: rejected — no lasting regression protection; a future change to the redness formula could silently break monotonicity with nothing to catch it.
- Stricter quantitative calibration (e.g. a correlation threshold against ground truth): rejected — every quantitative precedent found required a dermatologist rater; not achievable solo in a few hours, and no literature-grounded threshold number exists to adopt instead.
