# Dynamic Risk Register (Week 6 Sprint 1 ➔ Week 11 Sprint 2)

This register operationalizes the dynamic risk model specified in `04_Risk_Register_Evolution_SkinSense_v2.xlsx` using the **3-Step Process**, tracking how technical, CI/CD, security, and project-governance risks evolved from **Sprint 1 (Week 6)** into **Sprint 2 (Week 11)** and linking every claim to verifiable GitHub evidence (`EV01–EV10`).

> **Academic Honesty Note**:
> Sprint 1 (Week 6) and Sprint 2 (Week 11) registers are documented cleanly at project audit time against actual commits, PRs, Issues, and GitHub Actions runs. Closed risks are shown as resolved only where verified in CI/git; unfinished items (`R02` live `EXPO_TOKEN`, `R04` async peer click, `R06` stale `PR #49`) remain explicitly flagged as active open items.

---

## 1. 3-Step Risk Management Process

| Step | Action | Rule & Threshold |
|---|---|---|
| **Step 1 — Identify** | Scan commits, CI workflows, Issue/PR boards, branch rules, and env/tenant boundaries at Sprint checkpoints (Week 6, Week 11) and Change Requests (`CR-01..CR-05`). | Every newly introduced Change Request or failing CI run opens or re-scores a risk entry. |
| **Step 2 — Analyze** | Score **Likelihood (`1–5`) × Impact (`1–5`) = Risk Score (`1–25`)**:<br>- `16–25`: **Critical** (Immediate blocker fix)<br>- `10–15`: **High** (Planned mitigation within current Sprint)<br>- `5–9`: **Medium** (Monitor + guardrails)<br>- `1–4`: **Low / Residual** | Any risk scoring **`>= 12`** requires concrete **Mitigation Actions**, **Contingency Plan**, named **Owner**, and verifiable **GitHub Evidence**. |
| **Step 3 — Respond & Review** | Execute remediation PRs (`#86`, `#87`), re-run automated checks, update status cleanly (`Closed` / `Mitigated` / `In Review` / `Open Action Needed`), and record residual risk. | Risk can move to `Closed` only after CI / PR / GitHub verification passes. |
